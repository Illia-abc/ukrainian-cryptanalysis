# Криптоаналіз українського тексту

Python-проєкт для автоматичного криптоаналізу та розшифрування текстів українською мовою.

Проєкт заснований на [cryptanalysis] від DominicBreuker та адаптований для роботи з українським алфавітом і статистикою української мови.

## Можливості

На поточному етапі проєкт підтримує автоматичний криптоаналіз **простого шифру підстановки**.

Програма:

1. Завантажує статистику українських 4-грам.
2. Оцінює текст залежно від того, наскільки він відповідає природній українській мові.
3. Виконує пошук ключа підстановки.
4. Отримує найкращі варіанти розшифрування.
5. Виводить оцінку та ключ підстановки для кожного варіанта.

### Опис файлів

**`main.py`** — головний файл програми. Містить шифротекст, завантажує статистику n-грам, запускає криптоаналіз і виводить результати.

**`breaking/substitution.py`** — реалізує алгоритм криптоаналізу простого шифру підстановки.

**`score/ngram.py`** — містить клас `NgramScorer`, який оцінює текст на основі частот n-грам.

**`data/uk.py`** — завантажує статистику українських n-грам із файлу.

**`data/uk/quadrams.txt`** — містить українські 4-грами та кількість їх появи в статистичній моделі.

## Українські 4-грами

Програма використовує **статистику 4-грам** для оцінювання можливих розшифрувань.

4-грама — це послідовність із чотирьох символів. Наприклад:

```text
текст
стра
  аб
абв 
```

Пробіли також враховуються, оскільки вони містять корисну інформацію про межі слів.

Файл зі статистикою генерується на основі українського списку слів та даних про частотність слів.

Під час генерації перед і після кожного слова додаються два пробіли:

```python
word = "  " + word + "  "
```

Це дозволяє створювати 4-грами, які містять межі слів.

## Оцінювання тексту

`NgramScorer` обробляє текст як послідовність перекривних 4-грам.

Якщо 4-грама є в статистичній моделі, її логарифм імовірності додається до загальної оцінки. Для невідомих 4-грам використовується невеликий штраф.

**Вища оцінка** означає, що кандидат статистично ближчий до закономірностей української мови.

Оскільки використовуються логарифми ймовірностей, оцінки зазвичай є від'ємними. Наприклад:

```text
-5590 > -6327
```

означає, що `-5590` має кращу оцінку.

## Чому програма виводить 5 варіантів?

У `main.py` використовується:

```python
results = breaker.guess(
    ciphertext,
    n=5
)
```

Параметр `n=5` означає, що програма повинна повернути **5 найкращих кандидатів**, знайдених під час пошуку.

Алгоритм не розуміє українську мову так, як людина. Він математично оцінює можливі варіанти за допомогою статистики 4-грам, тому деякі кандидати можуть бути правильними, а деякі — ні.

Наприклад, під час тестування програма отримала:

```text
Варіант 1

Score: -5590.593
```

та:

```text
Варіант 2

Score: -5590.593
```

Обидва варіанти дали однаковий читабельний текст:

```text
Довбиш був багатий чоловік; він жив на самому кінці села...
```

Варіанти 3–5 мали значно нижчі оцінки та містили неправильні слова.

Це пов'язано з алгоритмом пошуку: він може знайти декілька локально хороших ключів підстановки, але не кожен отриманий кандидат обов'язково є правильним розшифруванням.

Якщо потрібен лише найкращий кандидат, можна змінити:

```python
n=5
```

на:

```python
n=1
```

## Виправлення завантаження українських 4-грам

Під час розробки виникла помилка:

```text
ValueError: Усі n-грами повинні мати однакову довжину
```

Проблема була спричинена використанням:

```python
line.strip().split()
```

під час читання статистичного файлу.

Цей спосіб неправильно працює з нашими даними, оскільки деякі 4-грами містять пробіли. Наприклад:

```text
  аб
```

Метод `strip()` видаляє пробіли на початку та в кінці рядка.

Тому завантажувач було змінено так, щоб перші `n` символів рядка розглядалися як n-грама:

```python
key = line[:n]
count = line[n:].strip()
```

Це зберігає пробіли всередині 4-грам і гарантує, що всі завантажені n-грами мають правильну довжину.
